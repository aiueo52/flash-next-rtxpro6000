### 4.0 wa's greedy text is not reproducible across server starts

- stack8 A1 vs A2 and B1 vs B2: 0/16 prompts with the same completion tokens and verify calls
  (`bench/stack/fingerprint.py`); within one start, repeats of a prompt also differ (FG1 probes).
- Likely mechanism: the wa controller reads position-0 confidences only once their copy has landed
  (`ConfidenceChannel.latest_position0`: `event.query()`, never a sync), so the width sequence depends on how far
  the CPU runs ahead of the GPU. The width sets the verify M (4/8/16 at bs 1), and the cached MoE tactics differ
  by M (gemm1 17/16/19, gemm2 57/57/59 for M 4/8/16), so the target logits can differ in the last bits and greedy
  argmax flips at near-ties. The start-up autotune itself is not the cause: its cache
  (`~/.cache/sglang/flashinfer/autotune/0.6.17/sm120/152015503b605a2e/`, 14 entries for M 1-64) has not changed
  since 09-07.
- Consequence: in wa, per-start noise includes different texts (different acceptance); the arm-level CI covers
  that. A bit-exact change cannot be checked in wa. w4 has one width and no controller, so it may repeat: the
  DT1 exactness check runs there (DT1 spec, status 15:05).
