# Long context (524288) on the shipped wa profile, 2026-10-02

*Edited for publication: details of the author's local launcher were removed.*

Question: "1M context, if realistic". Answer: 1M does not fit (the GPU is short by ~10 GB of KV/state at
13.5 KB/token, and the model only promises 262144); 524288 via the fork's qualified factor-2 YaRN is realistic; ~750k
is borderline.

## Measurement (GPU slot 21:40-22:00, `bench/ship/long_ctx.sh wa 524288`, LONG_EXTRA_ENV="WA_MEM_FRACTION=0.96")
- KV allocated 524288 tokens (target K+V 6.0GB, draft 0.5GB), mamba 16 slots 0.94GB, YaRN override on the cmdline.
- Needles (thinking off, temp 0): 16k sanity PASS 8.1s; 185k@0.5 PASS 17.5s; 480k@0.25 PASS 70.7s; 480k@0.75 PASS 71.4s.
  Prefill ~6.8k tok/s at 480k (10.8k tok/s on short chunks).
- Decode with LM Studio sampling: 185.5 t/s at 480k context, 284.4 t/s at 2k (same request shape).
- fnbench short prompts (1 run each, YaRN on): lmstudio -10.9/+8.7/-25.0/+19.4 %, greedy +0.3/+13.1/+34.4/-2.1 % vs the
  262144 ship smoke (code/prose-en/prose-ja/agent). Single runs; outputs differ under YaRN, so this is noise-level.
- GPU: 94554 MiB used after start-up, max 96220 MiB (min free 1667 MiB) with a 6.8GB desktop (Firefox 3.4GB).
  At the shipped 0.925 the pool would have been capped below 524288 with that desktop.

## Shipped (22:0x)
- `serve-fast.sh`: for wa only, CONTEXT_LENGTH > 262144 sets WA_MEM_FRACTION=${WA_LONG_MEM_FRACTION:-0.96}.
  <= 262144 is unchanged (no YaRN, 0.925).
- The default context length of the local launcher stays 8192; 524288 is opt-in.
- w4 and w16 were not measured above 262144 in this round.

## Beyond 524288 (not done)
YaRN factor 4 is outside the fork's qualified range; KV+state for 1M ~ +7GB over 524288 -> needs the desktop off the GPU,
KV offload (HiCache) or a second GPU.
